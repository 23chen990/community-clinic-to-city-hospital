## 1. 现在游戏里实际增加了什么

本轮**没有增加新系统**，把上传版里已有的东西修成它本来该有的样子：

| 修的东西 | 修之前 | 修之后 |
|---|---|---|
| 患者到院 | 第一位患者之后**再也不来人** | 按 4 人/分钟持续到院，带 ±30% 抖动 |
| 开业补助 | 每开一个科室都多发 150 | 只在 T01 发一次 |
| 病例末站倍率 | 完全没生效 | 按病例配置作用于路线最后一站 |
| 存档 | 写失败静默吞掉、坏档被覆盖 | 失败回滚并提示、坏档先备份、版本不符拒绝载入 |
| 房间面板 | 打开不暂停、按钮不刷新 | 打开即暂停、按钮随金币实时可用 |
| 手机横屏 | 面板越界、字和患者小到看不清 | 面板不越界、字号与患者有可读下限 |
| 登记 / 准入 | 配置写了但从不执行 | 登记并发真按 4 上上限、GP 准入等待有预算 |
| 工位与等候 | 一个房间所有人挤在同一个点 | 每个工位/等候位/登记位都有独立位置 |

## 2. 玩家目前能体验什么

- 打开页面就有患者自己走进来，一路 **入口 → 登记 → 全科 → 分支科室 → 出口**，不用点谁。
- 全科诊室里能看到**一个个独立的工位桌子**，谁在岗、谁在等，一眼分得清。
- 底部任务条 5 条带金额，引导玩家投币：**400 开处置室、1400 开检验室**。
- 投币反馈：金币数字变化 + 房间斜纹消失变白 + 提示 + 任务变绿勾。
- **扩容真的看得见**：花 700 给全科加到 2 工位、再加到 3 工位，
  房间里就多出一张桌子，同时能站 2~3 个人各干各的。
- 提速真的改时间：全科 Lv0 是 12.0 秒，面板上直接写下一级是多少秒。
- 点房间会**暂停**游戏再开管理卡，看完关掉继续，不会边看边漏人。
- 存档写失败会明确告诉你"本次改动已撤销"，右上角存档状态会变红。
- 手机横屏 667×375 这种小屏也能完整看到面板、关闭按钮和购买文案。

## 3. 还不能体验什么

- **没有真机体验**。iPhone / Android 真机横屏、真实触屏手感、真实刘海安全区都没测过。
- **没上 TapTap**。打包、宿主环境、提审都没做。
- **后台切走再回来**的行为只在逻辑层验证过（页面隐藏就不推进、回来不补跑），
  真机锁屏/系统回收的实际表现未测。
- **没有美术**。还是占位色块，没有人物立绘、动画、音效。
- **B 区 / C 区不可玩**，仍然是"后续内容"占位。
- **数值没调**。本轮刻意不改任何价格和时长；投资间隔是否舒服、1400 攒多久才合适，
  需要在修好的版本上重新实测再决定（见下一节）。

## 4. 下一步应该做什么

1. **先把这一版拿去做真机横屏实测**。这是当前最大的未测盲区，
   逻辑和布局问题已经解决，但触屏手感只能真机说了算。
2. **在修好的版本上重新实测真实投资间隔**，再决定要不要动数值。
   修复前"开检验室要攒多久"的观察是建立在断流版本上的，那个数据已经作废。
3. 真机通过之后再做 Cocos + TypeScript 迁移评估。这一步是**未验证的工作量**，
   不能沿用"机械搬运"的说法。
4. 以上都没通过之前，不扩 B/C 区、不加后台系统、不做美术。

## 5. 测试是否通过

**通过，但请注意边界。**

| 项目 | 结果 |

| 修复前失败复现（针对上传版冻结副本） | 47 条观察，**47 条复现了审计描述的缺陷** |

测试口径：回归脚本加载的是页面引用的**同一份** `config.js` 和 `game.js`，
按页面相同的顺序执行，**不在脚本里补任何游戏默认值**。
并且有一条断言专门删掉配置字段再加载，确认游戏会**拒绝启动**并指名缺哪个字段——
用来证明前面那些失败观察不是测试脚本造出来的。
